These are Xizt's CS:GO settings from 2012-12-13, the year of the ranking (see where these settings come from). Converted to CS2's crosshair system since the Sept 22, 2026 update, authored at 768p, Xizt's resolution; CS2 rescales it to your resolution.

Valve published no conversion formula. This uses a community reconstruction (small-indie-crosshair-company v0.19.1, model community-static-v11, CS2 build 2000922) that hasn't been checked against in-game captures.

Where these settings come from

  • Crosshair · 2012-12-13 · confidence low · github.com 1, 2, 3
    How the date is known

    Date of the commit that first added the preset: Skarbo/CSGOCrosshair e569127 ('First commit', 2012-12-13 16:12:46 +0100, Kris Skarbo). I checked this again in a full-history clone. This is the date the preset was published, so it shows Xizt's crosshair as the generator author understood it on or before that date. Every later commit that touches javascript/javascript.js keeps the same values: 8688713, 2787169, 214e315, 1f0c419, eacafda, and 8fcc53c/69fe7d2 on 2014-07-30. From 214e315 (2013-06-13) on, the preset only adds outline 0 and outline_draw 0.

  • Sensitivity · 2012 · confidence medium · github.com 1, 2
    How the date is known

    Worked out from the file's contents, because there is no publication date. Earliest date: player_medalstats_most_recent_time "1344978905" decodes to 2012-08-14 21:15 UTC (checked again with `date -u -d @1344978905`), so the file was saved after that. This value is NOT a personal save timestamp, though. The exact same value appears in GeT_RiGhT's and v1c7or's configs in setupgg/data, and v1c7or's config is clearly from a much later build (it has cl_crosshairstyle 4 and cl_operation_premium_reminder_op06). So the value only sets a lower bound. Latest date: the file has no cl_crosshairstyle but does have cl_dynamiccrosshair "0". That means the game build that wrote it did not have cl_crosshairstyle yet. In setupgg/data, 223 of the 229 config.cfg files with a crosshair have cl_crosshairstyle. Only six lack it, and every one of those six has cl_dynamiccrosshair. The two of them that carry a timestamp (f0rest and GeT_RiGhT) show 2012-08-11 and 2012-08-14. The Skarbo crosshair generator committed on 2012-12-13 (e569127, javascript.js header comment) already lists "cl_crosshairstyle ( def. \"0\" )" as a game cvar. So the file was most likely saved between 2012-08-14 and about 2012-12-13. That last step is an inference. The firm latest date is the git commit, 2016-04-29 08:50 +0200 (setupgg/csgo a7612a6). I changed the date from "2012-08" to "2012" because August is only the earliest possible month.

  • Resolution · 2016-04-30 · confidence medium · github.com 1, 2, 3
    How the date is known

    This is a latest-possible date: the git commit date of setupgg/csgo 1341e78 ('Init', 2016-04-30 17:14:04 +0200, Nic Malan), which replaced the earlier NiP-Xizt- config with this one. The files were later moved to setupgg/data in commit ef8c0a8 (2016-12-14). I diffed config.cfg, autoexec.cfg and video.txt against setupgg/data HEAD 5ba7974 and all three are byte-identical. The earliest possible date comes from the cvar cl_operation_premium_reminder_op06. KARRiGAN's config in the same dataset (setupgg/data player/karrigan/config/config.cfg) has only cl_operation_premium_reminder_op05, and its player_medalstats_most_recent_time is 1428149968 (2015-04-04 12:19 UTC). So a build written after 2015-04-04 still had no op06 cvar. No config in the dataset has both op05 and op06. Therefore Xizt's file, which has op06, was saved after 2015-04-04. The save date is between 2015-04-04 and 2016-04-30; the exact date is unknown. The file's own player_medalstats_most_recent_time (1358972187 = 2013-01-23 20:16 UTC) is not a save date (see the notes on the 2012 entry), so it only sets a weaker lower bound.

Settings from different sources are only combined when they agree (DPI is only paired with a sensitivity from the same source), so the eDPI never mixes eras.
