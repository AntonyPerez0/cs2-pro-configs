  • Old style 5 (Legacy) placed its bars at round(4 × height / 1200 + gap) at rest instead of Static Cross's trunc(4 + gap); at 768 that is 3 instead of 4 pixels, a reading of the old source that is unverified in the pre-update game.
  • Rounding and dropping the fraction give your old size or thickness different whole pixels; the converter rounds, as other converters and community measurements do, so the old game may have drawn it 1 px smaller.
  • Exported style 5 keeps the old style family. Its at-rest shape is assumed to match Static Cross, but it moves with inaccuracy and shots, which is neither modelled nor checked in game.

These are ScreaM's CS:GO settings from 2014, the closest to 2013 we found that can be converted (see where these settings come from). Converted to CS2's crosshair system since the Sept 22, 2026 update, authored at 768p, ScreaM's resolution; CS2 rescales it to your resolution.

Valve published no conversion formula. This uses a community reconstruction (small-indie-crosshair-company v0.19.1, model community-static-v11, CS2 build 2000922) that hasn't been checked against in-game captures.

Download .cfg

The CS2 console can reject a pasted line longer than 510 characters, so the full config comes in parts: press ~ in CS2, paste part 1, press Enter, then do the same with the next part. Or download the .cfg, save it in Counter-Strike Global Offensive/game/csgo/cfg/ and run exec scream-2013 in the console.

Where these settings come from

  • Crosshair, viewmodel, HUD and radar · 2014 · confidence low · github.com 1, 2, 3
    How the date is known

    Not an exact date, and the year is not certain: late 2013 is possible. Hard bounds: the game-written cvar player_medalstats_most_recent_time "1358107562" (2013-01-13 20:06 UTC) means the file was saved on or after 2013-01-13, and setupgg archived it on 2016-04-29 (commit e03e8c3). That timestamp does NOT place the file in 2013. The identical value, to the second, is also in ScreaM's G2-era config.cfg (entry 2, saved on or after 2015-07-10) and in snax's older setupgg config.cfg, so it was carried over from an earlier file. The set of cvars the game wrote into the file gives a tighter, inferred window of about late October 2013 to mid-June 2014. (a) Lower end: the file has econ_highest_baseitem_seen "62" and lobby_voice_chat_enabled, and lacks cl_showbackpackrarities. All nine setupgg/data configs with econ_highest_baseitem_seen 62 still have cl_showbackpackrarities and lack lobby_voice_chat_enabled. The latest of them, pronax's, has a medal-stats timestamp of 2013-10-18, so that older build was still in use on or after that day. (samersultan's game-written config.cfg, internal timestamp 2013-05-24 and committed 2013-05-30, does not have econ_highest_baseitem_seen at all.) (b) Upper end: the file lacks cl_hud_color, which is already present in a game-written config.cfg committed on 2014-06-15 (SkeyeLlama/BSides-CT-2014, internal timestamp 2014-05-18). It also lacks cl_crosshairgap_useweaponvalue, which samersultan's readme of 2014-10-10 calls "new". Most of the window falls in 2014, so the date is given as 2014.

  • Resolution · 2015 · confidence medium · github.com 1, 2, 3
    How the date is known

    A window from 2015-07-10 to 2016-04-30, not an exact date. Lower bound: the game-written cvar cl_operation_premium_reminder_op06 "1436534404" decodes to 2015-07-10 13:20 UTC. Upper bound: setupgg first archived the file on 2016-04-30 (setupgg/csgo commit b9ff730, 11:51 +0200). The in-file player name is "G2.Kinguin ScreaM SaiyajiN". Comparing cvar sets did not narrow the window further. The file has cl_crosshair_sniper_width, which RUBINO's setupgg config (op06 timestamp 2015-06-05) lacks. It lacks cl_clock_24hour and cl_mute_all_but_friends_and_party, which EliGE's config (op06 timestamp 2016-02-24) has. Both are consistent with the window. About 5.7 of the window's roughly 9.7 months fall in 2015, so 2015 is the more likely year but early 2016 is possible.

Settings from different sources are only combined when they agree (DPI is only paired with a sensitivity from the same source), so the eDPI never mixes eras.
